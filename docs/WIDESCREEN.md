# Experimental widescreen (0.11.1, patch)

Enable Settings > Display > Experimental 16:9. It starts off and saves your explicit choice. The world-view frame, including the original HUD-height allowance, changes from 1152 x 768 to 1365 1/3 x 768. The outer decorative border adds 31 logical pixels on each side, so its measured outer aspect is slightly different from 16:9. World sprites retain uniform scale; this does not stretch a screenshot or reveal more vertical world.

Login/title/character artwork and multi-Game connection/scene handovers retain the original layout. During STATE_PLAY the existing camera uses the wider logical extent; the original resize/cache invalidation allocates matching raster surfaces. Bottom HUD/chat/quest groups and dialogs remain centered at original dimensions; independent top controls anchor toward the left/right. The loaded game's original a_EdgeHud vector artwork replaces the plain frame from 0.11.0. Three clipped decorative instances preserve both corners/side sections and extend only the horizontal middle, retaining cracks, shading and gray HUD backing. No game frames are captured. The frame accepts no input and its objects/scale are changed only when necessary.

The 0.11.0 experiment missed two assumptions in the original terrain renderer. class_23.method_942 allocates ceil(576 * rasterScale), while method_1753 compared that integer against the unrounded product. Widescreen's fractional scale caused the entire terrain bitmap pool to be destroyed and allocated on every frame. The exact-hash guarded patch now rounds the comparison the same way as allocation; its 14-byte replacement preserves all branch/exception offsets and unrelated method bodies. The original four half-tile columns could also fail to cover the wider view when a lower staggered tile row was partly visible. Widescreen now requests six columns, preserving the even-count row algorithm, original tile sizes and pool budget. Switching back restores four.

The October 10 client's transition allocator had replaced the original scaled camera dimensions with a fixed 2048 x 1152 bitmap. At ordinary 1080p/1440p this mismatches the launcher's raster surface and can spill into, or leave seams beside, the gray margins. The reviewed correction restores the original allocator byte-for-byte. The isolated regression calls the actual Game.method_1947, reproduces the bad allocation in a baseline fixture, then checks matching dimensions after the correction. The original and corrected method bodies are full-hash checked, and the 38-byte substitution preserves branch/exception offsets.

Validation uses a guarded inactive Windows desktop. A baseline with the original method reproduces a cache rebuild on every rendered frame. Another baseline reproduces undrawn right-edge pixels with four-column coverage and a partly visible second row. The corrected actual class_23 cache and Game.method_1946 renderer reuse cache identity and pass solid-region pixel checks at six horizontal offsets, a vertical offset and all three detail levels. Thirty additional camera movements exercise actual tile eviction/reuse in the existing pool, without resetting the scene or cache; every sample has zero pixel errors and zero pool rebuilds. The fixture uses a smaller disposable pool to avoid baseline memory churn; this establishes the rebuild/coverage fix, not a measured combat speedup. Original offline Home/UI vector assets exercise real terrain drawing and the ornate border, with mock HUD roots and no game network initialization.

Additional checks cover real Flash layout/transition allocation at 1080p/1440p, repeated offset stability, left/center/right input conversion, frame click-through, zoom, fullscreen, toggling off and returning to menus. The real live title renders with widescreen enabled while retaining original artwork. Software-rendered captures are of test WebContents only; no input desktop capture, desktop switching, clipboard access, login or ClipCursor call is made. These tests deliberately do not claim an authenticated multiplayer combat session.

This is not validated against every live authenticated HUD, dungeon transition or encounter. Some maps may reveal blank/unfinished scenery, camera clamps may be designed for the original width, and complex fixed-width overlays may need additional positioning. Use the original layout if an overlay is misplaced. The preservation server does not advertise support for this modification; no claim of official compatibility, FPS gain or altered gameplay rules is made.
