# Dungeon Blitz Launcher

Version **0.30.0** (minor: native Flash gameplay with a separate GPU world renderer, replacing the Ruffle gameplay path used by GPU mode).

Singleplayer now includes its own local server. Settings → Connection → **Use singleplayer**, **Save**, then **Reconnect** starts a private instance on unused loopback ports. It stops and saves when this launcher closes or reconnects to multiplayer. Each launcher profile owns a separate local world; it does not import another server's accounts or saves. Local accounts are created inside that world through the game's own form. Internet or Minesa's server is not required for the bundled singleplayer content.

Singleplayer uses Original rendering with its separately guarded display, camera, controls and sound helpers. A saved GPU choice is kept for multiplayer. The current Minesa client works in both multiplayer renderers; its new Newbie Road door-trigger correction remains intact. Loading artwork now receives the widescreen centering offset during area travel, including pending game instances, without stretching the logo or text.

GPU startup falls back to Original if the client is unreviewed or the GPU host cannot start, while keeping your GPU preference. Equivalent SWF compression is accepted only when every decompressed source byte and header still match. Stalled or cancelled workers restore native rendering and release their resources; repeated GPU faults use bounded retry delays. Actual game-code, engine and artwork changes still require compatibility review.

The singleplayer code and dependencies are archived, while level artwork and audio remain ordinary files for reliable HTTP streaming. This keeps update paths short enough for the previous launcher’s updater. The new native updater and uninstall helper also handle deep custom installation and temporary rollback paths without changing Windows path policies. Signature, traversal, device-path, junction and running-game checks remain in place.

Settings → Display → **Game renderer: GPU world (Beta)** keeps the original Flash game, NPCs, dialogue, input and audio after Save and Reconnect. A separate WebGL2 worker draws retained world artwork and interpolates presentation transforms between unchanged game updates. Two bounded workers decode artwork in parallel. The adjustable cap is 15–1000; status counts completed changing world renders. The original counter measures native game updates.

The earlier 426 figure measured only GPU world renders in the previous runtime. It did not establish smooth NPCs or dialogue. The new account-free native artwork/HUD fixture held about 60 native updates/second while completing 406 changing world renders/second on an RTX 4080 SUPER. Its snapshot bridge supplied about 24 snapshots/second; the extra renders interpolate continuous transforms. These three rates are shown separately. This is not full-game 406 FPS, a combat benchmark or physical display scanout. Animation poses, simulation and server rules retain their native cadence; 1000 is only a ceiling. Original remains the default. Both multiplayer renderers now use the existing native Flash profile. Previous WebView2 sign-in storage is left untouched and is not copied. Local servers retain Original mode.

An activated autorun now continues when the game loses focus. Press the saved key again or a movement key after returning to stop. Opening Settings, hiding the game, disabling autorun or changing game context still stops it; no movement keys are sent to other applications.

Large dungeon backgrounds now keep their complete artwork in fullscreen by fitting each cached image within the original memory limit. Foreground geometry and game rules stay unchanged.

Settings → Controls → **Autorun key** lets you choose a key, then **Save**. Ö is the default; **Default** restores it in the draft. Choose a key unused by your game bindings. Press the selected key again or a movement key to stop. Typing and game-context safeguards remain intact.

Settings changes stay pending until you press **Save**. Switching categories keeps the draft. **Discard**, closing Settings, **Back to game** and Escape discard unsaved changes. A failed save leaves your edits available to correct. Saving applies game/display/audio options without reconnecting; a saved server address needs an explicit reconnect, and graphics acceleration needs a launcher restart.

Settings → Crosshair offers the untouched game pointer, **Original, recolored**, Cross, Dot or Ring. Recoloring retains the original shape, size, hotspot, transparency and dark outline; custom shapes offer size and outline controls. The preview uses the last original pointer reported by the game. Save applies changes inside the game only; text fields keep their text cursor. Windows cursor preferences stay unchanged. Crosshair options work independently of game bytecode compatibility.

Settings → Updates includes **Restore previous version & restart** when a distinct saved launcher and its complete build are present. It verifies that build against its signed release before closing this game, restores Windows version metadata and keeps both versions. Automatic updates turn off so the restored version stays selected. Internet access is required to fetch the signed verification manifest. An older launcher may lack compatibility with the current game; this restores the launcher, not Minesa's server deployment.

A settings snapshot is saved before restoring. Older versions may use defaults for options they do not support, such as original-pointer recoloring.

For an independently managed local server, enter its local URL manually, choose Original rendering, Save and Reconnect. Manual addresses remain external and do not start the bundled server. **Use multiplayer** selects Minesa again. Preset buttons and Save never reconnect by themselves. Unknown external clients retain their original code with a compatibility note; an unrecognized managed singleplayer client is blocked rather than routed to another server's ports. See [local client maintenance](docs/MINESA-UPDATES.md#local-singleplayer-clients).

Some local game data references absent Meteor/FireBrand Shot icon names. For two reviewed local UI assets, the launcher supplies those names using the game's original Meteor/Fireball vector artwork. This separate presentation repair works even when the main client is unsupported. It retains every original asset tag and changes no server file, ability data or game method. Unrecognized assets and multiplayer origins remain unchanged.

Settings uses a slate stone frame matching the title bar, quiet category navigation, thin gold accents and purple sound tracks. It opens on Display and remembers your selected category and its scroll position while the launcher is open. A fixed category list becomes a horizontal tab row in smaller windows; the heading and Back to game button stay in place. Layout/camera and size/detail options are grouped separately, with performance settings under an expandable section. Audio uses aligned category sliders beneath master volume. Controls collects cursor and mount shortcuts, while Connection and Updates explain when an action reconnects or closes the launcher. Existing preferences remain intact; Original centered hotbar is unavailable while 16:9 is off, without losing your saved choice.

For new failures after a Minesa deployment, start with [the game-update repair guide](docs/MINESA-UPDATES.md). The launcher can now retain enhancements when a new revision preserves the reviewed hooks and interfaces, even if unrelated game code or appended symbols change. It keeps Minesa's changes intact. Incompatible contracts still run unchanged; saved preferences survive. This reduces compatibility releases, without promising that every future game update will work automatically.

Run **Dungeon Blitz Launcher Setup.exe** once, then open **Dungeon Blitz Launcher** from Start or the desktop shortcut. The single installer includes the complete runtime; there is no ZIP to unpack. It installs for your Windows account in `%LOCALAPPDATA%\Programs\Dungeon Blitz Launcher` by default and does not request administrator access. Windows Settings → Apps provides the normal uninstall option. A desktop shortcut is optional during setup. Existing launcher preferences and Flash sign-in storage stay in their existing locations; uninstall preserves them.

Rerunning this Setup checks the latest release through the same pinned signature/hash pipeline. It skips payload replacement when already current, keeps a newer installed build instead of downgrading, and upgrades to a newer signed release when available. It uses one installation and preserves preferences/login data. The check runs without opening the game or reading its profile. Running games block installation; Setup never closes them. A first/offline install keeps the complete bundled build when GitHub is unavailable. Already distributed Setup files cannot acquire this new behavior retroactively; use the 0.15.0-or-newer Setup once.

The portable option remains available: run **Dungeon Blitz Launcher.exe** in this source folder, keeping the matching release folder beside it. Both root executables always correspond to the latest packaged build. Source stays in Downloads/BlitzBrowser; the historical folder name is retained. [Download the Windows installer](https://github.com/Daniel-Prizer/dungeon-blitz-launcher/releases/latest).

The launcher automatically opens Minesa's live Dungeon Blitz in one isolated original Flash session. Tabs, address/search bar, homepage, bookmarks, history, downloads, browser navigation and the experimental Ruffle/socket bridge have been removed.

Modern-browser playback now works at [the new official address](https://dungeonblitz.theminesa.studio/) (without the `r`). Its custom Ruffle build renders the public class screen and passes our offline graphics/HUD enhancement probe. The old address still requires Flash. This release keeps the verified Flash host while authenticated gameplay, persistence, audio and performance are evaluated for a modern replacement. See [the October 12 investigation](docs/CLIENT-FEATURES.md#modern-browser-investigation-12-october-2026).

**Change Character** in the top bar reloads the current game page and returns to the original character screen using the saved game login. It retains launcher preferences and does not apply a pending server change. Settings uses a fixed frame across all six panes; longer content scrolls inside it.

The game surface follows the launcher and cannot be dragged or resized separately. Its edges remain game input. Move and resize the launcher normally using its title bar and outer window frame.

The windowed title bar is 32px high and uses a muted Dungeon Blitz wordmark, with no ready/status label. A matching DB monogram supplies the Windows icon.

Settings → Display → Show FPS counter enables a small counter in the upper-left gray margin. It is off by default, including profiles upgraded from versions without the checkbox; pressing Save applies your choice without reconnecting. It counts the actual game-loop Flash frame events over elapsed milliseconds and updates about once a second. Low and High show the smallest and largest measured averages whose samples ended within the last 30 seconds; these are not 1% lows or individual frame times. It accepts no mouse/keyboard focus, so clicks still reach the game. It hides when zoom leaves no side margin. The number is game frame cadence, not the configured target, monitor refresh, network latency or measured GPU scanout.

Game links on the selected game origin reload the configured game page. User-activated external HTTP/HTTPS links open in your default browser, never inside the Flash host. Privileged schemes and credential-bearing URLs are blocked; unsolicited external popups are denied.

## Settings

- Original centered hotbar: in 16:9, restores the native compact health/abilities, companion slots, XP, quest/menu row and chat to the center beneath the wider world. Defaults off; changes apply after Save.
- Centered camera: keeps the character in a small central horizontal zone in either layout, while retaining native room boundaries and smoothing. Frozen/scripted views stay original. Defaults off; Settings → Display → Save applies and remembers it.

- Experimental 16:9: off by default. Widens the logical view during play without stretching sprites or changing game clocks. Login/character selection keeps its original artwork. Active scene transfers retain the wide frame. Health/hotbar and party controls anchor left, chat/top-right controls anchor right, and menus/social center independently. The quest panel uses the extra middle width; its text and Map label keep their original proportions. Utility buttons distribute across that space. Building inspection replaces the health/combat section with its native upgrade controls at the left edge; the shared HUD backing continues to the quest panel. World labels retain their origin, and the corrected raster crop transform prevents scale-dependent cached-label shifts. Original modal dimming covers the full wider view, including inset mattes. The original ornate vector border and bottom decoration preserve their sides/corners and have no input or uncontrolled animation. Home interiors retain their original scene and player geometry inside the same wide frame/HUD. Reviewed passive wall/floor artwork fills narrow indoor background gaps without clipping players; terrain and buildings are never stretched. The backmost sky is rasterized from its original vector at the final resolution. No extra vertical world, free camera movement or generated playable scenery is added. Some private live maps/overlays may still need adaptation; this is a client presentation experiment, not official server widescreen support. See [widescreen testing and limitations](docs/WIDESCREEN.md).

- Automatic updates: enabled by default. Checks our GitHub release 10 seconds after startup and every six hours. From 0.13.0 an incompatible game client also triggers one immediate check per launcher session. The opt-out applies to all automatic checks. Updates require an Ed25519 signature plus all archive/file hashes and download in the background without interrupting the game. Closing installs only an update already showing **downloaded and verified**; closing itself does not check GitHub, and an unfinished download is retried on a later launch. To update immediately, use Settings → Check for updates, wait for verification, then close or choose Install & restart. Previous root executable/build are retained. New game revisions can reuse matching reviewed hooks automatically. If the structural contract and exact-revision adapters both reject them, unsupported patches remain off until a compatibility release; the launcher never guesses bytecode offsets. Works in the installed app and complete portable layout without administrator access. Installed updates refresh Windows Apps and record files for uninstall. Public builds through 0.14.0 need one manual Setup upgrade to repair their ASAR verification/cleanup bug. Verification now reports progress and has an abortable time limit.
- Master: 0–100 in steps of 1; fresh profiles start at 100. Purple fill follows the value, including keyboard changes, number entry and restored settings; the unused track is slate. Zero silences game audio. Controls only Windows audio sessions belonging to the game and its child processes; leaves device/master volume and other apps alone. The game's own sound controls still apply. New audio sessions and active output devices are checked every second.
- Player, Music, Environment and Creatures: independent 0–100 sliders in steps of 1, all defaulting to 100. Player covers player characters/abilities and menu sounds; Creatures covers non-player entity sounds; Environment covers ambient streams and room/world sounds. Classification uses the emitting entity, not guessed sound names. Category gain multiplies the game's own volume and Master. Existing channels and loops update without reconnecting; music/ambient fade timing remains unchanged. Separate categories require the reviewed Minesa client; unsupported revisions disable those sliders while Master still works. Flash can quantize a composed channel gain to a 1% step.
- Lock cursor inside the window: off by default. Left Alt by itself toggles the actual checkbox on/off, including enabling an unchecked lock, and saves that choice for the next launch. The Settings checkbox changes this preference after Save. Windowed confinement includes the top menu, so Settings and Fullscreen remain reachable. Sides and bottom retain a 12-logical-pixel inset, scaled for DPI; fullscreen applies that inset to every game edge. Settings, minimisation, switching apps and close release confinement. Alt+Tab and Alt+F4 remain normal Windows shortcuts. Click the shortcut button and press a single key to record it; Escape cancels, and F11 remains reserved for fullscreen. Modifier bindings toggle on release; held-key repeats and saved-setting acknowledgements cannot toggle repeatedly. Shortcuts apply only while the visible game/launcher is foreground and do not activate during key capture.
- Game URL: defaults to https://dungeonblitzr.theminesa.studio/. Accepts HTTPS pages and HTTP on localhost/127.0.0.1/[::1]. Credentials and privileged URL schemes are rejected. Save the URL, then use Apply URL & reconnect. An address edit never silently interrupts gameplay. The isolated runtime's HTTP access is restricted to that selected origin; pages requiring resources on another origin may not work.
- Game scale: Fit entire game, or 50–300%. Larger-than-Fit views crop edges. The reviewed Minesa client redraws its own game bitmap at the requested size inside a full-window Flash stage. Normal 1080p/1440p rendering does not enlarge a fixed low-resolution bitmap in Chromium. Windows DPI is compensated in the host; exceptionally large zooms use a bounded 4096×2730 layout budget with residual browser scaling. Margin clicks preserve focus and pass native aiming and attack events to the game. The Lost Focus splash is removed; normal focus and key cleanup remain.
- Graphics acceleration requires a launcher restart. Background activity can be disabled.
- Rendering resolution: 100% is the default and retains the sharp native rendering. 75% and 50% reduce the game's backing bitmap while keeping the displayed picture size and normal animation speed. They draw approximately 44% and 75% fewer pixels, respectively, with softer enlargement. This can reduce CPU raster work when a Flash thread is busy; it is not a guaranteed combat FPS improvement. The FPS counter keeps its on-screen size. Unknown client revisions disable this setting.

The dedicated game host disables legacy Chromium native-window occlusion heuristics to avoid incorrectly treating its separate game surface as covered. Explicit background settings remain available. This is a potential client-stall mitigation; the reported delayed NPC interactions have not been reproduced or established as resolved. Fullscreen notifications now follow actual visibility changes and are refreshed on game activation. The isolated tests verify native state, but cannot visually verify Explorer taskbar behavior.

The game uses original native Flash rendering. Neural enhancement, comparison and FPS target controls are removed; saved experimental graphics preferences are discarded. The new FPS counter is observational. Game scale remains available and animation timing is unchanged. The display adapter reuses the original cache-invalidation/resize path. Version 0.11.0 restores the original scale-aware scene-transition allocation in the reviewed October 10 client, replacing its fixed 2048×1152 canvas with matching native dimensions. Game clocks and packet handlers are unchanged; the optional widescreen mode changes camera extent. Graphics acceleration is now forwarded to the separate game host as well as the local shell.

F11 toggles fullscreen. Escape stays with the game to close its menus; it never leaves launcher fullscreen. In launcher Settings, Escape dismisses the dialog or cancels key capture. Ctrl+, opens Settings even while the game has focus. Fullscreen has no title/exit strip. Closing and reconnecting do not show leave-game confirmations.

Settings → Controls → Left Shift mounts / dismounts adds an optional alias for your current in-game mount binding. Your original key still works; changing it in the game changes the alias automatically. Left Shift still types normally in chat and login, and right Shift stays unchanged. Key capture and unsupported clients disable the alias. It sends a single paired key event through the game's original input path; equipped-mount, combat and server restrictions still apply. Left Shift cannot simultaneously be the cursor-lock shortcut.

While the game is foreground, inactive Sticky Keys and Filter Keys activation prompts are temporarily suppressed. Existing enabled accessibility features stay enabled. Original shortcut flags restore when opening Settings, switching apps or closing the game; a bounded local recovery record restores them after a launcher crash. Tests use a fake Windows API and make no system accessibility changes.

The companion controls sit in a separate gold ornament beside the native ability recess. The quest and utility panel has its own border and padding. The custom Dragon Ore counter was removed because its artwork and font did not match the native currencies.

Your existing original Flash sign-in profile is retained. Old browser-only preference fields are discarded when the launcher saves preferences. Launcher settings retain their historical local profile directory for migration; they are not sent to the server. Clipboard text is read only when you explicitly paste into the game and stays inside its process.

## Development and testing

Use Node.js, npm and a JDK with java/javac available (JDK 17 or newer): npm install, npm run prepare:game, then node scripts/prepare-owned-singleplayer.cjs with the path to the reviewed server repository, and npm start. The server import reads immutable Git objects from commit a409ee06a3231a67acc22f4d953c77d5b92e17b9, installs pinned production dependencies and excludes accounts/saves/environment; it never builds from unrelated working changes. Preserve an existing import and build in fresh staging when replacing it. The initial prepare:game imports Flash from an existing official Dungeon Blitz R installation without modifying it. Later builds can reuse the complete hash-verified import even after that application is uninstalled. Missing or altered imported files fail verification. npm run package creates a versioned portable build and refreshes the root executable, then verifies packaged source, runtime hashes and security fuses. npm run installer builds the single Setup EXE and refreshes its root copy; Inno Setup 7.1.0 is downloaded with a pinned checksum and verified publisher signature, then unpacked in portable mode on the inactive test desktop. PowerShell 7 (`pwsh`) is required for compiler signature verification. The compiler is confined to .test-tools, with no system-wide installation, associations or shortcuts.

npm run test:installer: install/reinstall, every installed file hash, root launch verification, Windows registration, shortcut targets, running-process refusal, downgrade refusal, updated-file uninstall and unrelated-file/profile preservation. Uses a unique test registration identity and shortcuts inside a disposable folder on the guarded inactive desktop, never your actual Start menu, desktop or profile. The future-update payload is a disposable fixture; the signature/download pipeline has separate tests.

npm run test:updater: complete signed pipeline under actual Electron, physical ASAR hashing, tamper rejection, progress and failed-stage cleanup. Add -- --packaged to exercise the packaged updater. Node-only update tests do not establish Electron filesystem behavior.

npm test: URL/link validation, settings migration, audio delta validation, paste behavior and the actual native cursor policy.
npm run test:launcher: hidden launcher UI and live Flash rendering.
npm run test:native: same user-flow checks on a guarded inactive Windows desktop, native layout/focus, fullscreen, cursor configuration and real Windows audio-session attenuation using a silent fixture.
npm run test:input: live Flash email/password typing and paste compared with typed-reference pixels.
npm run test:render: real game captures and native bitmap dimensions at 1080p/1440p, bounded 50–300% zoom, animation-rate equality, fullscreen and focus.
npm run test:transition: actual terrain-cache/render-method regressions, transition allocation before/after at 1080p/1440p, widescreen input/HUD restoration and native detail changes, original offline Home/UI assets, plus live unauthenticated title rendering. Offline artwork tests require the reviewed current public assets in .test-tools/wide-live-assets or an explicit BLITZ_TEST_ASSET_DIR; archived UI assets must not silently substitute for the current client.
npm run test:fps: actual game-loop counter at 1080p/1440p/fullscreen, independent fixture frame counts at 30/60/100 targets, forced CPU stalls and mouse click-through. Frame-rate controls exist only in the unshipped fixture.
npm run test:margins: live full-window Flash bounds, side-click focus and rendered magnification; a separate Flash fixture verifies actual stage MouseDown/MouseUp and aim coordinates.
npm run test:window: real Windows hit-test queries at every game edge/corner and exact native placement after launcher move/resize/maximize/fullscreen/settings. No OS pointer input is sent.

The presentation changes and audio adapter require either a matching reviewed structural contract or an exact reviewed client revision. The structural path preserves unrelated game updates and appended symbols automatically; changed hooks or interfaces require review. Rejected revisions run unchanged and show a compatibility note in Settings. The client is fetched from the selected game origin normally; no game executable, credentials or gameplay data are bundled or replaced.

Automated fixtures never reuse account data. Separately, explicitly authorized manual live QA can copy one origin-specific saved session into a disposable private profile; its account values and captures are never published. Tests never switch desktops, move your mouse, send OS keyboard input or use your clipboard. Cursor ClipCursor calls are deliberately disabled in automated integration tests; state/shortcut routing is tested without physically confining your pointer. The inactive desktop has no Explorer, so taskbar visibility cannot be visually verified there. Login-screen tests do not prove authenticated dungeon combat, audio quality or long-session stability.

Building the small game-window Node-API module downloads a checksum-verified Zig 0.13.0 compiler and official Node-API headers into .test-tools. These build tools are not installed system-wide and are excluded from the portable package. The module uses the stable Node-API surface and is built from src/GameWindow.c; there is no C++ ABI dependency or third-party input-hook library.

See SECURITY.md for the remaining Flash and legacy Chromium risks. No claim of zero vulnerabilities, measured FPS improvement or Chromium feature parity is made.

The build downloads checksum-verified JPEXS 26.3.0 and the publicly served reviewed Minesa client into .test-tools. Only a bounded, hash-validated audio delta and the launcher-owned adapter are shipped; the complete game SWF and compiler are excluded. Building verifies that 3,746 original method bodies outside the reviewed audio hooks remain byte-identical.

See docs/CLIENT-FEATURES.md for historical neural and frame-interpolation experiments, including why the live enhancer was removed. RIFE frame generation was tried offline at 720p and 360p, with equal-duration motion checks. Live frame generation is not shipped; 60/120 distinct game frames have not been established.

## Public source repository

The repository contains launcher source, generated brand assets and development tests. Local profiles, test captures, executable builds and the imported Flash/runtime binaries are excluded. The initial import needs the official Dungeon Blitz R application; subsequent builds can reuse the verified local runtime copy. This is a community launcher; game definitions and private server behavior belong to their respective owners.

Autorun: Ö toggles walking in the direction the character faces, through the current in-game movement binding. A second Ö, manual movement, typing or map/menu input releases it; an activated run survives ordinary focus loss. Controls has an explicit Save checkbox to disable it. The binding follows the typed Ö character on your keyboard layout; it does not install a global hotkey.

The world canvas refreshes behind the map instead of retaining the native still image. No simulation clocks, game ticks, dungeon travel or session/rejoin behavior changes.
